# 干花素材抠图需求说明

## 一、任务

把 `flowers/` 里的 14 张干花照片去除白色背景，输出**带透明通道**的 PNG。

素材用于网页装饰：干花会叠放在米白色纸质背景上，并与其他元素互相遮挡。因此**边缘质量和镂空完整度**比什么都重要——有白边或者花瓣缝隙没镂空，放到页面上会非常明显。

---

## 二、输出参数（硬性要求）

| 项目 | 要求 | 说明 |
|---|---|---|
| 格式 | **PNG-24 带 Alpha 通道** | 不要 PNG-8（只有 1 位透明，边缘会成锯齿）；不要 JPG（不支持透明） |
| 色彩模式 | RGB，8 位/通道 | 不要 CMYK |
| 尺寸 | **保持原始像素，不缩放、不放大** | 原图 1632–2048px 不等，保留原尺寸 |
| 裁切 | 裁到花朵外接矩形，四边留 **2% 空白** | 不要留大片多余透明区，也不要贴边裁切 |
| 文件名 | **与原文件名完全一致** | 代码里已按此命名引用，改名会导致图片加载失败 |
| 交付方式 | 全部放在一个文件夹里 | 不要打包成分层 PSD，只要最终 PNG |

---

## 三、边缘与细节要求（重点）

### 1. 不能有白边
原图是白底，最常见的问题是抠完后花瓣边缘残留一圈白色像素。放到米白背景上单看不明显，**但这些花会叠在深色照片或彩色区域上，白边会立刻暴露**。

要求：边缘做**去边缘杂色**处理（Photoshop：图层 → 修边 → 去边，1px；或用"移去白色杂边"）。

### 2. 羽化控制在 0.3–0.5px
不要为了消白边而大幅羽化。羽化过度会让干花边缘发虚，失去干花特有的脆硬质感。

### 3. 花瓣之间的空隙必须镂空
这是最容易出错的地方。以下位置的背景**必须是透明的，不能填成实心**：
- 花瓣与花瓣之间露出的背景
- 枝条分叉处的三角形空隙
- 细茎两侧
- 花蕊丝之间的缝隙

特别注意 `07-spray-amber.png`（枝条散开、空隙极多）和 `08-sprig-rust.png`（细枝居多）。

### 4. 保留半透明
干花花瓣很薄，原图里有些花瓣是**半透明**的（能透出后面的东西）。这些区域的 Alpha 值应当是**中间值**，不要一律拉成 100% 不透明。

尤其是：`05-cosmos-white.png`、`10-ranunculus-white.png`、`14-orchid-pink.png` 这三张，薄花瓣特征最明显，处理成实心会丢掉干花的通透感。

### 5. 不做任何修图
不要调色、不要加锐化、不要磨皮、不要补全残缺的花瓣、不要加投影。**只做去背，其余保持原样。**

## 四、难点提示

以下 4 张是浅色花配白底，**花瓣本身接近白色**，自动工具（AI 一键抠图、魔棒）几乎必然会把浅色花瓣误判成背景吃掉。这几张需要手工检查：

| 文件 | 难点 |
|---|---|
| `01-daisy-cream.png` | 白色雏菊花瓣与白底几乎同色 |
| `05-cosmos-white.png` | 整朵近白，且花瓣极薄 |
| `10-ranunculus-white.png` | 米白花瓣 + 细绿茎，茎容易被抠断 |
| `12-blossom-cream.png` | 奶白色花簇，多层花瓣叠压 |

---

## 五、验收标准

收到文件后逐项检查，任何一项不过即退回：

**1. 透明通道是否真实存在**

在 macOS 终端里运行（把路径换成实际文件夹）：

```bash
sips -g hasAlpha /path/to/flowers/*.png
```

每一张都必须显示 `hasAlpha: yes`。显示 `no` 的说明根本没有透明通道，直接退回。

**2. 白边检查**

把图片放到**纯黑背景**上看（预览 App 里切换深色背景，或丢进任意支持深色底的看图工具）。花朵边缘不应出现任何白色轮廓线。这一步在白底上看不出来，必须用深色底。

**3. 镂空检查**

同样在黑底上看，花瓣间隙、枝条分叉处应当**透出黑色**。如果这些位置是白色或灰色块，说明没镂空。

**4. 细节完整性**

对照原图逐张比对：
- 细茎有没有被抠断
- 浅色花瓣有没有被吃掉
- 花蕊有没有丢失

**5. 尺寸与命名**

文件名与原文件一致，像素尺寸不小于原图。
